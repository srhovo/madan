8.4.3 · 修复「服务类型候选点不中」

## 这次修的是什么

在「服务类型」输入框里输入内容后，下方会弹出候选项目。点它**没有任何反应**，
面板直接消失、输入框里还是原来的字 —— 看起来像是「这一下被跳过了」。

8.4.1 与更早版本都正常。这是 8.4.2 引入的回归。

## 为什么会这样（因果链）

8.4.2 加了「点空白结束输入态」：点输入框外面的空白，就收键盘、让底部操作栏回来。
当时它的判定挂在 **pointerdown** 上 —— 这个时机比候选自己的处理更早。

候选的选中逻辑挂在 **mousedown** 上，靠 `preventDefault()` 保住输入框焦点：

1. 手指按下 → 先触发 pointerdown → 此时判定「点的是空白」→ 把输入框 blur 掉
2. 输入框失焦 → 它的处理器用 requestAnimationFrame 收起候选面板
3. 真机上 touchstart 与 touchend 之间**必然跨一帧** → 上面那步 rAF 先执行 → 候选列表被清空
4. 手指抬起 → touchend 派发 mousedown → 要点的那个候选已经不在 DOM 里 → 点击落空

所以现象是「点了没反应，直接跳过」。桌面浏览器连续点击中间不插帧，测不出来，
只有在手机/平板的真实触摸里才暴露。

## 怎么修的

判定时机从 pointerdown 挪到 **pointerup**：此时候选早被选中、焦点也已交给下一个字段，
不再和 mousedown 抢时序。同时补三道判据，任何一条不成立都不干预：

- 焦点必须还是按下时那个（变了说明这次点击已被别的处理器接管）
- 起手点或落点落在可交互区就放过
- 期间滚动过、或手指滑走超过 12px，不算「点一下空白」

可交互白名单也补齐并分组标注来源。8.4.2 只写了 `.suggest-list`，
而服务类型候选用的是 `.type-suggest-list` —— 一字之差，整块候选失效。

## 连带核对

「点空白结束输入态」本身没有退化：聚焦 → 底部操作栏隐藏，点空白 → 恢复显示。
这一点仍与 8.3.57 做过对照（旧版点空白后焦点黏在输入框里、操作栏不回来）。

## 防线

新增 2 条静态断言 + 1 条真机断言：

- 静态：判定必须在 pointerup，且 pointerdown 只做记录不做 blur（盯根因）
- 静态：白名单必须覆盖全部候选面（.type-suggest-list / .boss-suggest-list /
  .ap-quick-chip / .history-item / .boss-memory-item）
- 真机：注入一条价格规则 → 聚焦服务类型 → **分两步派发触摸并在中间留一帧** →
  断言候选名真的填进了输入框

最后那条是关键。连续 tap 测不出来，必须拆开 touchStart / touchEnd 才复现真机时序 ——
这也正是 8.4.2 当初能「测了全绿」的原因。

反向验证：把实现改回 pointerdown 并去掉白名单里的候选面，6 条断言同时变红，
真机那条直接打印 `"防线探针"→"防线探针"`。

## 验证

- 全量防线：30 套，发版时跑全量（含变异测试）
- 界面套件：41 项全过，19 条反向验证全红
- 触摸时序审计（分步派发）：服务类型候选 / 老板候选 / 历史记录 / 清除按钮 / 锁定按钮 /
  计算按钮，7/7 全过；同一脚本在 8.4.2 上红 1 条，在 8.4.1 上全绿
- 点空白：5 处空白全部能结束输入态，5 类按钮不被误伤

## 没有改的

输入框字号、平板列数、44px 命中区、弹窗无障碍、存储状态标志 —— 全部未动。
