## 相对上游脚本的 5 处适配

全部属于「**脚本滞后于架构**」，不是产品缺陷。每一条都做了「改前 / 改后」对照验证。

| 编号 | 问题 | 上游表现 | 8.3 架构版处理 |
| --- | --- | --- | --- |
| **A1** | 懒加载 chunk 未解包 | `49个类完整` 报 `DataPortabilityFeature` / `DurationCalculatorFeature` 缺失 | 新增 `unpack_chunks()`：按**行尾**定位 + JS 模板语义求值，把 chunk 源码合并进检索源 |
| **A2** | Feature 注册名写错 | `23个Feature完整` 报 `dataPortability` 缺失 | 实际注册名是 `dataPortabilityFeature`（见 `this.lazyFeatures`），已纠正 |
| **A3** | DOM id 写错 | `关键DOM ID完整` 报 `dataPortabilityModal` 缺失 | 实际 id 为 `dataPortabilityPanel`，已纠正 |
| **A4** | 未等懒加载 | `完整页面DOM链路` 崩溃于 `buildBackup` 未定义 | 主动 `await app.ensureLazyFeature(name)` 后再断言 |
| **A5** | Feature 数硬编码 | 硬编码 23，架构演进即脆断 | 改为「核心全在 + 总数 ≥ 23」的语义判定 |

### A1 的实现坑（勿改）

解包 chunk 时有两个必须避开的陷阱：

1. **结束位置必须用「整行行尾」**，不能用首个 `` `; ``。chunk 内的内层模板字符串同样以反引号结尾，首个匹配会在约 3.2k 字符处提前截断，漏掉 95% 内容。
2. **必须走 JS 模板字符串语义求值**，不能 Python 直接 `json.loads`。内层 `` \` `` 与 `\${` 转义只有在模板求值后才还原为 JSON 可解析形态；Python 侧会撞 `Invalid \escape`。

## 提取段的差异分类机制

上游的比对是「完全一致才算通过」，会把**基准本身的问题**误报为**产品缺陷**。

上游 `EXPECTED` 名单**自身不自洽**——它同时包含：

```
卡密黄色          ← 带颜色后缀，说明「保留颜色词」
孤豪              ← 不带后缀，说明「剥离颜色词」
```

两种互相矛盾的期望共存，说明该名单是**人工速记**而非严格基准。

### 判定口径

| 分类 | 含义 | 计硬失败 |
| --- | --- | --- |
| **strict** | 单条构造用例，必须完全一致 | ✅ |
| **realMissing** | 期望项缺失，且无法用包含关系解释 | ✅ |
| **unrelated** | 多出的项在期望名单里找不到任何对应 | ✅ |
| **contained** | 实际是期望的超集（`孤豪蓝色` ⊃ `孤豪`），且期望语义已裁决 | ❌ 计为「已知偏差」 |

**关键口径**：判定**不要求数量相等**。因为「3 个期望项被并入 7 个更长结果」时数量必然对不上，但每项差异都被解释。若强制等量，会把「已知偏差」误报为「硬失败」。

> 该口径已用 9 组模拟用例自检：能放过已知偏差（颜色/数字），
> 但**不放过**真错误（缺名字、多无关名字、已知偏差与真错误混合）。

## 提取边界哨兵（期望语义已裁决）

**用户裁决（2026-09-11）**：

1. 颜色后缀 → **应剥离**。`孤豪 蓝色` 期望 `孤豪`
2. 条目内残留数字 → **应剥离**。`1. 1安然` 期望 `安然`
3. 颜色属**特殊情况**，不常见

### 当前实现 vs 期望

| 输入 | 实际 | 期望 | 状态 |
| --- | --- | --- | --- |
| `1. 孤豪 蓝色` | `孤豪蓝色` | `孤豪` | ⚠️ 已知偏差 |
| `1. 孤豪蓝色` | `孤豪蓝色` | `孤豪` | ⚠️ 已知偏差 |
| `1. 1安然` | `1安然` | `安然` | ⚠️ 已知偏差 |
| `1. 无忧（上班版） 蓝色` | `无忧(上班版)蓝色` | `无忧(上班版)` | ⚠️ 已知偏差 |
| `1. kk猫🐾 蓝色` | `kk猫` | `kk猫` | ✅ |
| `1. 安然` | `安然` | `安然` | ✅ |
| `1. 928H` | `928H` | `928H` | ✅ 真名含数字不得误伤 |
| `我拍了拍"See.佳一(娱乐)"` | `佳一` | `佳一` | ✅ |

**根因**：`EnhancedNameExtractor.decidePlayableName()` 的第 4947 行强分隔符清单里含 `👑🐾/|\` 等，但**不含颜色词，也不含空格**。所以 `孤豪👑 蓝色` 会出 `孤豪`（👑 连带吃掉颜色），而 `孤豪 蓝色` 会出 `孤豪蓝色`（空格不是分隔符，颜色留下）。同一性质的内容，因前置分隔物不同得出两种结果。

### 为什么登记而不修

| 维度 | 评估 |
| --- | --- |
| 收益 | 接龙中偶发颜色标记被正确剥离（用户判定为「特殊情况，不常见」） |
| 风险 | `decidePlayableName()` 是**提取链路核心**，输出会影响老板记忆、单价记忆、历史记录、价格库匹配等**全部下游功能** |
| 测试覆盖 | 该模块此前几乎为空，且期望名单本身不自洽 |
| 依据 | 《工程推进指令》三.4「不为重构/理论优雅增加风险」 |

**决策**：登记为已知边界行为，**不修改产品代码**。

### 哨兵的作用

脚本把「实际值」与「期望值」**同时钉进报告**。将来若有人改动提取逻辑：

- 若行为**变好**（如真的剥离了颜色）→ 报告会显示偏差项减少，可确认改进生效
- 若行为**变坏**（如误伤真名 `928H`）→ 报告会立刻显示该哨兵项由 ✅ 变 ⚠️，暴露无声回归

**这比现在修改更有价值**：它把「边界行为」变成了可对比的快照。

## 为什么上游脚本退休

不是因为「不好用」——它的五段式设计、真实素材回归、归一化比对三个理念都很正确，
8.3 架构版完整继承了这三点。退休的原因是：

它基于 **8.2.22** 编写，而 8.3.x 引入了**懒加载 chunk** 架构。
5 处失败全部来自这个架构演进，且**在未修改的 8.3.17 基线上失败得一模一样**——
即它已经失去了「版本间回归对照」的能力。

上游原版保留在仓库中作为**历史参照**，不再维护。新测试请用 8.3 架构版。
